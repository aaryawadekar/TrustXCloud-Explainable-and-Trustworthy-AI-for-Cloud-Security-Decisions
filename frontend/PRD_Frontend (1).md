## 1. Product Overview

### 1.1 Product Name
**Explainable Cloud Security Dashboard (ECSD)**

### 1.2 Problem Statement
Cloud security systems generate large volumes of alerts. Traditional AI-based threat detection systems may identify an event as suspicious without clearly explaining *why* the prediction was made. This makes it difficult for security analysts to understand, validate, and trust AI-generated alerts.

The frontend will provide an intuitive investigation interface that visualizes:

- Security events and alerts
- AI-generated risk predictions
- Risk scores and classifications
- Explainable AI (XAI) factors
- IAM-related activity
- Event timelines and contextual information

### 1.3 Frontend Goal
Transform raw security, ML, and XAI outputs into a clear interface that answers three questions:

1. **What happened?**
2. **How risky is it?**
3. **Why did the AI flag it?**

# 2. Target Users

## 2.1 Security Analyst
Primary user responsible for monitoring and investigating suspicious cloud activity.

**Needs:**
- Quickly identify high-risk events
- Filter and investigate alerts
- Understand AI predictions
- View the factors contributing to a prediction

## 2.2 Researcher / Project Evaluator
User evaluating the performance and explainability of the research prototype.

**Needs:**
- View model predictions
- Compare risk distributions
- Observe XAI explanations
- Understand how the system presents AI decisions

---

# 3. Product Scope

## In Scope

- Security overview dashboard
- Alert and event listing
- Filtering and searching
- Event investigation view
- AI risk-score visualization
- SHAP/XAI explanation visualization
- IAM activity visualization
- Event timeline
- Model-performance visualization
- Integration with backend REST APIs
- Responsive desktop-first interface

## Out of Scope for MVP

- Training ML models
- Generating SHAP explanations in the frontend
- AWS infrastructure management
- Real-time threat detection engine
- Authentication implementation unless required by the project
- Security response automation
- Full SIEM functionality

The frontend consumes data generated by the backend and ML/XAI services.

## 5.3 Alert Investigation Page

### Purpose
Provide complete information about a selected security event.

### Sections

#### A. Alert Summary
- Event ID
- Classification
- Risk score
- Confidence score
- Alert status
- Detection timestamp

#### B. Event Metadata
- User identity
- IAM role
- Source IP
- Event name
- Cloud service
- Region
- Timestamp

#### C. AI Explanation (Primary Research Feature)

The interface must clearly answer:

> Why did the AI classify this event as suspicious?

Example:

```text
AI RISK ANALYSIS

Risk Score: 94%
Classification: HIGH RISK

TOP CONTRIBUTING FACTORS

Unusual Source IP       +0.32
Abnormal Access Time    +0.25
Rare API Action         +0.19
High Request Frequency  +0.15
Known Device            -0.04
```

Requirements:
- Positive and negative feature contributions must be distinguishable
- Show the relative importance of features
- Display a human-readable explanation summary
- Support backend-provided SHAP values

#### D. Natural-Language Explanation

Example:

> This activity was classified as high risk primarily because it originated from a previously unseen IP address, occurred outside the user's normal activity period, and involved an unusual API action.

The frontend displays this explanation; it does not generate it.




# 8. Non-Functional Requirements

## Performance
- Dashboard should load efficiently with large event lists
- Use pagination or virtualization where required
- Cache API responses appropriately

## Usability
- Important risk information must be visible immediately
- AI explanations must be understandable to non-ML experts
- Avoid unnecessary cybersecurity jargon

## Responsiveness
- Desktop-first
- Functional on tablets
- Basic mobile support

## Accessibility
- Keyboard-accessible interactions
- Semantic HTML
- Do not rely exclusively on color to communicate risk

---

# 9. Success Criteria

The frontend MVP is successful if a user can:

1. View the overall security state.
2. Identify high-risk alerts.
3. Open a specific event.
4. Understand the event's metadata and context.
5. View the AI risk prediction.
6. Clearly understand why the AI flagged the event.
7. Navigate related IAM activity and timelines.

# 12. Key Product Principle

> **The frontend is not simply a security dashboard. Its primary research contribution is making AI security decisions understandable to humans.**

Therefore, the **AI Explanation interface** should receive the highest design and development priority.
